# Mini NPU Simulator

Python으로 **MAC(곱셈 후 누적 덧셈)** 연산을 직접 구현하고, 숫자로 표현한 패턴이 어떤 필터와 더 비슷한지 판단하는 콘솔 프로그램입니다.

## 1. 준비물과 실행 방법

- Python **3.8 이상** (작성 및 테스트 환경: Python 3.13.17)
- 외부 라이브러리 설치 불필요 (`json`, `time` 등 Python 기본 기능만 사용)

`main.py`와 제공받은 `data.json`을 **같은 폴더**에 둡니다.

```text
1-3_mini-npu/
├── main.py
├── data.json
└── README.md
```

Windows PowerShell에서 해당 폴더로 이동한 뒤 실행합니다.

```powershell
py main.py
```

실행 후 메뉴에서 다음 기능을 선택합니다.

- `1`: 3×3 필터 A/B와 패턴 직접 입력
- `2`: `data.json`의 6개 패턴 분석
- `3`: Cross/X 패턴 자동 생성 (보너스)
- `4`: 2차원 배열과 1차원 배열의 MAC 속도 비교 (보너스)

## 2. MAC 연산이란?

MAC은 **Multiply–Accumulate**의 줄임말로, 숫자들을 **같은 위치끼리 곱하고 그 결과를 모두 더하는 연산**입니다.

예를 들어 십자가 패턴은 이렇게 표현합니다.

```text
0 1 0
1 1 1
0 1 0
```

이 패턴에 같은 십자가 필터를 적용하면 점수는 `5`입니다. X 필터를 적용하면 가운데 칸만 겹쳐서 점수는 `1`입니다. 따라서 십자가 필터 점수가 더 높습니다.

이번 과제의 MAC은 일반적인 행렬곱이 아닙니다. **두 행렬의 같은 위치에 있는 값을 곱해 모두 더하는 방식**입니다. `mac()` 함수에서는 두 개의 `for` 반복문으로 이 계산을 수행합니다.

## 3. 프로그램 기능

### 모드 1: 사용자 입력 (3×3)

1. 필터 A를 세 줄로 입력합니다.
2. 필터 B를 세 줄로 입력합니다.
3. 비교할 패턴을 세 줄로 입력합니다.
4. 두 필터의 MAC 점수를 계산하고 A, B 또는 `UNDECIDED`로 판정합니다.
5. MAC 연산을 10회 반복하여 평균 시간(ms)을 출력합니다.

각 줄은 `1 0 1`처럼 **공백**으로 구분하거나 `1,0,1`처럼 **쉼표**로 구분할 수 있습니다. 숫자가 세 개가 아니거나 숫자로 바꿀 수 없는 문자를 입력하면 안내 문구를 보여주고 다시 입력받습니다.

직접 확인한 예시에서는 A 점수 `8.0`, B 점수 `8.0`이 나왔고, 두 점수가 같아 `UNDECIDED`로 판정되었습니다.

### 모드 2: data.json 분석

`data.json`에는 `filters`와 `patterns`가 있습니다.

- `filters`: 5×5, 13×13, 25×25 크기의 Cross/X 필터
- `patterns`: 비교할 입력 행렬과 예상 정답(`expected`)
- 예: `size_13_2`는 **13×13 크기의 두 번째 패턴**을 의미합니다. 이 이름에서 `13`을 읽어 `size_13` 필터를 선택합니다.

프로그램은 패턴과 필터의 크기를 검사한 뒤 MAC 점수를 계산합니다. JSON 구조나 행렬 크기가 잘못된 케이스는 가능한 한 **그 케이스만 FAIL**로 처리하고 다음 케이스를 계속 검사합니다.

### 모드 3: 패턴 자동 생성 (보너스)

`3`을 고르면 행렬 크기 N을 입력합니다. **3 이상의 홀수**만 입력할 수 있어요. 예를 들어 `5`를 입력하면 5×5 Cross와 X가 자동으로 만들어집니다.

- Cross: 가운데 **가로줄과 세로줄**에 1을 넣습니다.
- X: 두 **대각선**에 1을 넣습니다.
- 생성한 Cross를 입력 패턴으로 삼고, Cross/X 필터의 MAC 점수를 비교합니다.
- 5×5 Cross의 자기 자신에 대한 MAC 점수는 9입니다.

### 모드 4: 2D와 1D 성능 비교 (보너스)

`4`를 고르면 두 가지 MAC 계산 방식의 시간을 비교합니다.

- **2차원**: `matrix[i][j]`처럼 행과 열을 차례로 읽습니다.
- **1차원**: `flatten()`으로 행렬을 한 줄로 펼친 뒤 `matrix[k]`처럼 읽습니다.
- 계산한 MAC 점수가 같은지 확인하고, 각 방법을 **1,000회 반복**해 평균 시간을 비교합니다.

### 라벨 정규화

JSON에서 십자가를 `+` 또는 `cross`라고 쓸 수 있기 때문에 내부에서는 이름을 통일합니다.

| JSON에 적힌 이름  | 프로그램에서 사용하는 이름 |
| ------------ | -------------- |
| `+`, `cross` | `Cross`        |
| `x`, `X`     | `X`            |

이 과정이 없다면 같은 모양인데 이름이 달라서 정답 비교가 틀릴 수 있습니다.

### epsilon 동점 판정

실수는 컴퓨터에 저장하거나 계산할 때 아주 작은 오차가 생길 수 있습니다. 예를 들어 `0.9`와 `0.8999999999999999`는 엄밀히 같은 숫자는 아니지만 거의 같습니다.

이번 프로그램은 두 점수 차이의 절댓값이 **`1e-9`(0.000000001)보다 작으면** `UNDECIDED`로 판정합니다. 이 값은 가장 작은 실수가 아니라 **프로그램에서 정한 허용오차**입니다.

## 4. 결과 리포트

### 4-1. JSON 분석 결과

실제로 실행한 결과는 **전체 6개 / PASS 3개 / FAIL 3개**입니다.

| 케이스         | Cross 점수          | X 점수               | 판정        | 예상 정답 | 결과   |
| ----------- | -----------------:| ------------------:| --------- | ----- | ---- |
| `size_5_1`  | 0.9               | 0.8999999999999999 | UNDECIDED | X     | FAIL |
| `size_5_2`  | 8.9               | 0.1                | Cross     | Cross | PASS |
| `size_13_1` | 0.3               | 14.700000000000008 | X         | X     | PASS |
| `size_13_2` | 7.499999999999997 | 7.5                | UNDECIDED | Cross | FAIL |
| `size_25_1` | 4.9               | 4.899999999999999  | UNDECIDED | X     | FAIL |
| `size_25_2` | 52.9              | 0.1                | Cross     | Cross | PASS |

### 4-2. 실패 원인 분석

1. `size_5_1`은 두 점수 차이가 약 `1.11e-16`으로 매우 작습니다.
2. 따라서 epsilon 규칙에 따라 `UNDECIDED`로 판정했지만 예상 정답은 X이므로 FAIL입니다.
3. `size_13_2` 역시 점수 차이가 약 `2.66e-15`로 epsilon보다 작습니다.
4. 예상 정답은 Cross이지만 실제 판정은 `UNDECIDED`라서 FAIL입니다.
5. `size_25_1`의 점수 차이도 약 `1.78e-15`이므로 `UNDECIDED`가 됩니다.
6. 이 케이스의 예상 정답은 X이므로 FAIL입니다.
7. 이 세 가지는 **프로그램이 멈춘 오류가 아니라 판정 결과와 예상 정답이 다른 경우**입니다.
8. 점수 차이가 아주 작아지는 이유는 데이터의 값과 실수 계산의 반올림이 함께 영향을 줄 수 있습니다. 출력만으로 어느 쪽이 원인인지 단정하지는 않았습니다.
9. `normalize_label()`은 `+`와 `cross`를 같은 Cross로 바꾸어 **라벨 표기 차이**를 해결합니다.
10. `validate_matrix()`는 잘못된 행·열 개수 등 **데이터 구조 문제**를 MAC 계산 전에 찾아냅니다.
11. 점수 계산을 잘못한 **로직 오류**, JSON의 **데이터·스키마 오류**, 작은 점수 차이에 관한 **수치 비교 문제**를 구분해 살펴보는 것이 중요합니다.
12. FAIL 개수를 줄이기 위해 임의로 epsilon을 없애거나 예상 정답을 수정하지 않았습니다. 과제의 비교 규칙을 지키면서 실패 원인을 기록했습니다.

### 4-3. 성능 측정 결과

다음 표는 **각 크기에서 MAC 함수 1회를 10번 측정한 평균 시간**입니다. 행렬은 성능 비교를 위해 모든 값이 1인 테스트 행렬을 사용했고, 파일 읽기와 화면 출력 시간은 측정에 포함하지 않았습니다.

| 크기    | 평균 시간(ms) | 위치별 곱셈 횟수(N²) |
| ----- | ---------:| -------------:|
| 3×3   | 0.002440  | 9             |
| 5×5   | 0.004160  | 25            |
| 13×13 | 0.017620  | 169           |
| 25×25 | 0.065050  | 625           |

### 4-4. 시간 복잡도 O(N²) 분석

1. 한 변의 길이가 N인 행렬은 N개의 행과 N개의 열이 있습니다.
2. `mac()`은 바깥 반복문으로 N개의 행을 순회합니다.
3. 각 행마다 안쪽 반복문으로 N개의 열을 순회합니다.
4. 따라서 위치별 곱셈을 총 **N × N = N²번** 수행합니다.
5. 예를 들어 3×3은 9번, 25×25는 625번의 위치별 곱셈이 필요합니다.
6. 이 반복문 구조 때문에 MAC 함수의 시간 복잡도는 **O(N²)**입니다.
7. 실제 측정에서도 행렬이 커질수록 평균 실행 시간이 늘어나는 경향을 확인했습니다.
8. 다만 측정 시간은 계산 횟수와 정확히 같은 비율로 증가하지는 않았습니다.
9. 그 이유는 Python 반복문 실행 비용, 운영체제 상태, 매우 짧은 측정 시간에 따른 변동 등이 있기 때문입니다.
10. 따라서 **O(N²)는 코드의 반복 횟수로 설명**하고, 시간 측정 결과는 그 경향을 확인하는 자료로 사용했습니다.

## 5. 보너스 과제 결과

### 5-1. 1차원 배열 최적화 실험

기존 2차원 행렬의 값을 **같은 순서 그대로 한 줄의 리스트로 옮겨서** 연산했습니다. 두 방식 모두 각 칸을 한 번씩 계산하므로 시간 복잡도는 **O(N²)**로 같습니다. 다만 1차원 방식은 리스트 인덱스를 한 번만 사용하므로 Python 환경에서 실행 시간이 달라질 수 있습니다.

아래는 직접 실행한 **1,000회 반복 평균** 기록입니다. 단위는 밀리초(ms)이고, 숫자가 작을수록 빠릅니다.

| 행렬 크기 | 2D 시간(ms) | 1D 시간(ms) | 1D 속도 향상(약) |
| --- | ---: | ---: | ---: |
| 3×3 | 0.001179 | 0.000605 | 1.95배 |
| 5×5 | 0.003478 | 0.001408 | 2.47배 |
| 13×13 | 0.018237 | 0.011598 | 1.57배 |
| 25×25 | 0.051107 | 0.047923 | 1.07배 |

이번 측정에서는 네 크기 모두 **1차원 방식이 더 빨랐습니다.** 하지만 항상 1차원이 더 빠르다는 뜻은 아닙니다. 컴퓨터 상태나 재측정에 따라 값이 달라질 수 있습니다. 또한 **2차원 → 1차원 변환 시간은 제외**한 비교이므로, 전체 처리 시간까지 무조건 빨라진다고 할 수는 없습니다.

### 5-2. Cross/X 패턴 자동 생성

`generate_pattern(n, shape)` 함수는 숫자 N과 모양 이름(`Cross` 또는 `X`)을 받아 N×N 배열을 만듭니다. 같은 크기의 행렬을 손으로 모두 입력하지 않아도 된다는 장점이 있습니다.

예를 들어 N=5일 때 X는 다음과 같습니다.

```text
1 0 0 0 1
0 1 0 1 0
0 0 1 0 0
0 1 0 1 0
1 0 0 0 1
```

5×5 Cross를 자기 자신과 MAC 계산했을 때 **9점**이 나오는 것도 확인했습니다. 짝수 크기나 3보다 작은 크기는 오류 메시지와 함께 다시 입력받도록 구현했습니다. (직접 재입력 테스트 결과는 별도로 기록할 수 있습니다.)

## 6. 직접 확인한 테스트

- 정상적인 3×3 입력에서 A/B MAC 점수 계산 및 판정 확인
- `1 1`처럼 한 줄에 숫자가 두 개뿐일 때 재입력 안내 확인
- 같은 점수의 두 필터가 `UNDECIDED`로 판정되는 것 확인
- 잘못된 행 길이를 `validate_matrix()`가 잡아내는 것 확인
- JSON의 6개 케이스가 중간에 중단되지 않고 분석되는 것 확인
- 2D와 1D MAC 점수가 5로 일치하는 것 확인
- 2D와 1D 계산 시간 1,000회 평균 비교
- 5×5 X 패턴 자동 생성과 Cross 자기 MAC 점수 9 확인
